# Design: Spatial residual-influence audit of corrective unlearning (SAM ViT-B, Kvasir-SEG)

Status: draft for pre-registration. Layout generated by `make_layout.py` (master seed 20261114).

## 1. Question, unit, response

**Primary question.** Among unlearned models whose output masks look clean, does a spatial
internal audit score measured *before* any perturbation predict whether the corrupted ring
re-emerges under (a) prompt perturbation and (b) continued fine-tuning, **better than
output-level metrics alone**?

**Unit of randomization and replication: the training run (seed).** A seed fixes the
corruption assignment, the flagged subset, data order, augmentation and decoder init.
Images and pixels are *repeated measurements within a model*, not replicates.
Pooling 120 test images x 4 models as n = 480 would be pseudoreplication.

**Responses.**
| Name | Definition | Level |
|---|---|---|
| Ring-FP (output) | Fraction of ring-band pixels predicted foreground (threshold 0.5) | image, model |
| Dice / boundary-F | Standard segmentation quality on the true mask | image, model |
| Audit score A | Ring-band internal signal standardized against the clean-model reference (Sec. 4) | image, model |
| Re-emergence R | Ring-FP after perturbation minus the oracle's Ring-FP under the same perturbation; "re-emerged" if above the oracle's 95th percentile | image, model |

## 2. Conditions (randomized complete block; block = seed)

Every seed produces all conditions from the **same** corruption assignment and the **same**
nested flagged subsets, so comparisons between conditions are within-block.

| Condition | Trained on | Role |
|---|---|---|
| Clean | All train images, original masks | Reference distribution for the audit (null) |
| Corrupted | All train images, 40% with ring | Positive control: the audit must fire here |
| Oracle | Train images minus **all** corrupted | Exact-unlearning target; negative control |
| Unlearned: SSD, SAP | Corrupted model + flagged subset (+ trusted set for SAP) | Approximate unlearning |
| Unlearned: RmF | Retrain from scratch minus **flagged** subset | Goel et al.'s retraining baseline |

Flag fraction (of corrupted samples): **10, 25, 50, 100%**, as nested subsets.
RmF at 100% equals the oracle by construction. Use it as a pipeline consistency check.

**Flagged-subset draws.** SSD and SAP run after training and are cheap, so each SSD/SAP condition
at 10, 25 and 50% flagging gets **5 independent flagged-subset draws** (nested within each draw).
At 100% flagging every draw is identical, so it gets 1 model. RmF needs retraining and gets 1 draw.

**Per seed:** 3 references + 4 RmF + 2 x (3 x 5 + 1) SSD/SAP = 39 models (36 unlearned).
**Seeds:** 1 development seed (0) + **6 confirmatory seeds (1-6)**, set by the power analysis in Sec. 8.
That is 234 confirmatory models and 49 from-scratch fine-tunes in total, including the development seed.

## 3. Data partitions

1. **Leakage control first.** Kvasir-SEG has no patient IDs. Group near-duplicate frames
   (perceptual hash + SSIM threshold) into clusters and split **by cluster**, never by image.
2. Partitions, all disjoint at the cluster level:
   - **Train pool** (corruption is applied here): about 65%
   - **Trusted set** (always clean, in every model's training; used by SAP and for recovery fine-tuning): about 10%
   - **Validation** (hyperparameter selection, dev seed only): about 10%
   - **Kvasir test** (audit and recovery): about 15%
   - **External test: CVC-ClinicDB.** It has sequence IDs, so it gives a patient-independent check.
3. **Audit evaluation strata** (within each model): flagged-corrupted train images,
   unflagged-corrupted train images, clean train images, test images.
   Flagged images measure sample-specific memory. Test images measure a learned
   "draw a ring" tendency.

**Corruption assignment.** Within each seed, select 40% of the train pool by
**stratified random sampling on polyp-area tercile**, because ring area scales with polyp size.
Ring = dilate(mask, d + w) minus dilate(mask, d), computed at the 1024-px model resolution.
Fixed primary geometry (for example d = 0, w = 15 px). Fix this before the confirmatory seeds.

## 4. The audit signal and its controls

Signals, all extracted on the ring band and on matched control bands:
- Pre-threshold decoder logits
- Decoder intermediate tokens projected to the spatial grid
- Image-encoder spatial features (only meaningful if the encoder is fine-tuned, see below)

**Standardization.** For each pixel band, A = (signal of model - mean over Clean-model seeds) / SD
over Clean-model seeds. **Fit the Clean reference on the development seed plus held-out clean
seeds only**, never on the models being scored.

**Specificity controls (required).** Ring bands sit next to boundaries, where logits are elevated anyway.
- **Offset control.** Also compute A on a band at a *different* offset (for example d = 30 px). A real
  memory signal should be specific to the trained offset.
- **Boundary control.** Compare against an inner band of the same width inside the true mask.
- **Frozen-encoder sanity check.** If the encoder is frozen, encoder features must give A ≈ 0 for every model.

**Fine-tuning scope.** Fix one scope before starting, for example the decoder plus LoRA on the
encoder. If the encoder is frozen, any encoder-level audit claim is void.

## 5. Recovery arms

**(a) Prompt perturbation.** This is test-time only, with no weight updates. It is fully crossed
within each model and image, giving 14 prompt conditions (`prompt_conditions.csv`) with
5 random draws per image:
- Box expansion: 0, 10, 20, 30%. Note that an expanded box *contains* the ring region, so this is the most direct probe.
- Points: 1, 3 or 5 points, with shifts of 0, 10 or 25% of the polyp radius.
- Box + point.

Use fixed per-image perturbation seeds so every model sees identical prompts. This pairs the comparisons.

**(b) Continued fine-tuning on the trusted set.** One trajectory per model, with checkpoints at
0, 100, 300, 1000 and 3000 steps (`recovery_finetune.csv`). Run it identically on the oracle so
there is a reference for drift that has nothing to do with the corruption.

*Optional stronger test:* relearning, meaning a small fine-tune on a handful of **unflagged**
corrupted samples. Compare the speed of ring re-acquisition with the oracle's.

## 6. Fairness and blinding

- Tune hyperparameters for SSD, SAP and RmF on **seed 0 only**, with an **equal tuning budget**
  per method. Select by output-level criteria (validation Dice + Ring-FP on flagged images),
  **never by the audit score**, because that would make the analysis circular.
- Freeze the code, thresholds, band definitions and analysis script before running seeds 1-6.
  Record the commit hash.
- Run the models in the randomized `exec_order` from `runs.csv`, so that no condition coincides
  with a code or driver change.
- Exclude the development seed from all confirmatory statistics.

## 7. Pre-specified analysis

**H1 (signal validity).** A is higher in Corrupted than in Oracle and Clean at the trained offset,
and not at the control offset. Mixed model: A ~ condition x band + (1|seed) + (1|image).

**H2 (residual influence).** Some unlearned models have output Ring-FP indistinguishable from the
oracle (equivalence margin pre-specified, TOST) but A significantly above the oracle.

**H3 (prediction, primary).** Restrict to the models that pass the "looks clean" criterion from H2.
The outcome is R, either as re-emergence yes/no or as a continuous value, under each recovery arm.
Compare two predictors:
- M0: output-level metrics at step 0 (Ring-FP, Dice, mean ring logit after thresholding)
- M1: M0 + A

Report the change in AUC (or in R²) and a likelihood-ratio test. Model level: logistic GLMM with
(1|seed). Image level: R ~ A + M0 + (1|seed/model) + (1|image).

**Secondary.** Effect of flag fraction x method on A and R. Test whether A from encoder vs
decoder features predicts differently.

## 8. Replication and power

Scripts: `power_sim.py` and `power_sim_reps.py`. Results are in `power_results*.csv` and `power_curve.png`.
There is no pilot data yet, so every input below is an **assumption**, swept for sensitivity.

**H3 test as simulated.** Model-level regression R ~ A + M0 + seed blocks, keeping only the
models that look clean (lowest 75% of M0 within each seed). The two recovery arms are co-primary,
so alpha = 0.025 each (Bonferroni). Type I error under a null where A tracks M0 but has no extra
information: 0.020-0.027 (target 0.025), so the test is calibrated.

**Assumed data-generating process (standardized).**
- Latent residual memory m: variance 40% from condition, 20% from seed, 40% specific to the model.
- Correlation of the output metric with m: rho0 = 0.3. This is weak by premise, because the models "look clean".
- Correlation of re-emergence with m: rhoR = 0.8.
- Correlation of the audit with m: rhoA from 0.4 to 0.7. This is the unknown that matters.

**Power for H3 (primary, 75% look clean), 2,000 simulations per cell, MC SE about 0.01:**

| rhoA | 1 draw, 5 seeds | 1 draw, 8 seeds | **5 draws, 6 seeds** | 5 draws, 8 seeds |
|---|---|---|---|---|
| 0.5 | 0.46 | 0.68 | **0.95** | 0.98 |
| 0.6 | 0.65 | 0.86 | **0.99** | 1.00 |

The stringent version adds condition fixed effects, so A must predict re-emergence *within* a
method and flag fraction. With 5 draws and 6 seeds it reaches 0.64 (rhoA 0.5) to 0.85 (rhoA 0.6),
so it is **secondary**, not confirmatory.

**Decision: 6 confirmatory seeds with 5 flagged-subset draws per SSD/SAP condition.**
Adding seeds alone is inefficient, because the 12 models per seed are what limit the degrees of
freedom. Cheap post-hoc draws raise power more per GPU-hour than extra full training runs.

**H1 (positive control: corrupted vs oracle, paired by seed, alpha 0.05).** With 6 seeds the
minimum detectable standardized difference is d_z = 1.43 (1.68 with 5 seeds). A working positive
control should far exceed this. If it doesn't, the audit signal itself has failed, which is
informative.

**Assumptions to recheck on the development seed (before any confirmatory run):**
1. The correlation between draws from the same corrupted parent. The simulation treats draws as
   only sharing the condition and seed effects. If draws are much more alike than that, their
   value drops toward 1 draw, and the seed count must rise toward 8-10.
2. A rough rhoA and rho0 from seed 0's 36 unlearned models. If seed 0 suggests rhoA < 0.5,
   rerun `power_sim_reps.py` with the observed values. The development seed is excluded from
   confirmatory analysis, so using it to set n is legitimate.
3. The fraction of models that look clean. At 50% instead of 75%, power drops (see `power_results.csv`).

## 9. Compute (rough)

There are 49 from-scratch SAM ViT-B fine-tunes on fewer than 1,000 images each. SSD and SAP
are post-hoc and cheap. Prompt arm: 234 models x ~150 test images x 14 conditions x 5 draws
≈ 2.5M decoder passes, but the image embedding is computed once per model and image, so only
the decoder reruns. Fine-tuning arm: 234 models x 5 checkpoints. Use **get-available-resources**
before committing to a GPU plan.

## 10. Threats to validity

- **Synthetic corruption.** A geometric ring is not a real annotation error. Claims stay limited
  to this corruption family unless a second type (for example, systematic boundary erosion) is added.
- **Boundary confound.** Handled by the offset and inner-band controls. Report them even if they're inconvenient.
- **Leakage.** Handled by near-duplicate clustering and the external CVC-ClinicDB test.
- **Prompt as a confounder.** An expanded box changes what counts as "inside", so R is always
  compared against the oracle under the *same* prompt.
